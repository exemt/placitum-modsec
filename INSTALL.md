# Установка

Инспектор не слушает сеть: он подписчик очереди на шине. Ни адреса, ни Service ему не нужно, и
добавление копии не трогает ни узел защиты, ни конфигурацию. Обычно его поднимает фундамент
установки (`placitum-core`).

## Что нужно рядом

| Компонент | Обязателен | Зачем |
| --- | --- | --- |
| NATS | да | очередь `waf.req.modsec`, аудит, журнал, поколение профилей |
| Redis: обменник | при проверке тела | тело крупнее порога модуль кладёт туда и присылает локатор |
| Redis: внутренний | да | блобы поколения: профили, наборы данных, политика |
| Контроллер | да | шлёт профили поколением |
| `geo` | при записи в наборы по сети или системе | кодер: анонсы и номер системы |

**Обменник — не «желательно».** Без адреса инспектор ответит на тело `allow` с пометкой
`store_unconfigured` в аудите, то есть проверка тела молча выключится. Недостижимый обменник,
наоборот, — отказ старта: так и задумано.

## Переменные

| Переменная | По умолчанию | Что |
| --- | --- | --- |
| `NATS_URL` | `nats://127.0.0.1:4222` | шина |
| `REDIS_URL`, `REDIS_INTERNAL_URL` | из `inspector.conf` | обменник и внутренний Redis; окружение перекрывает файл |
| `WAF_MODSEC_SUBJECT` | `waf.req.modsec` | подписка |
| `WAF_MODSEC_NAME` | `modsec` | имя в реестре инспекторов и в кадре присутствия |
| `WAF_MODSEC_PROFILES` | `./profiles`, в образе `/app/profiles` | профили из образа: то, на чём процесс поднимается до первого поколения |
| `WAF_MODSEC_DATA` | `<профили>.applied`, в образе `/var/lib/waf/modsec` | куда раскатка кладёт применённое поколение |
| `WAF_MODSEC_STATUS_MAP` | `./status_map.yaml` | какой странице отказа соответствует статус правила |
| `WAF_MODSEC_VERSIONS` | `2` | версии схемы сообщения; модуль шлёт `2` |
| `WAF_MODSEC_GEO_ADDR` | пусто | кодер гео (`host:port`). Пусто — записи в наборы по сети и системе отвечают отказом |
| `WAF_MODSEC_GEO_TIMEOUT` | `500ms` | ожидание кодера в бюджете сообщения |
| `WAF_MODSEC_GEO_NEG_MAX` | `0` | потолок отрицательного кэша кодера; `0` — его умолчание |
| `WAF_MODSEC_DENY_RULE_IDS`, `WAF_MODSEC_DENY_TAGS` | пусто | правила и теги, срабатывание которых — безоговорочный отказ, а не вклад в счёт |
| `WAF_MODSEC_RESUME_MAX` | `4 × queue_max` | сколько незавершённых проверок фазы ответа держится в памяти |
| `WAF_MODSEC_RESUME_TTL` | `30s` | сколько ждать ответа, пока проверка запроса ещё помнится |
| `WAF_MODSEC_SECRETS` | пусто | каталог секретов, если профили на них ссылаются |
| `WAF_MODSEC_WORKERS` | число ядер | воркеры пула |
| `WAF_MODSEC_QUEUE_DEPTH`, `WAF_MODSEC_QUEUE_FULL`, `WAF_MODSEC_CONF` | из `inspector.conf` | очередь: глубина, поведение при переполнении, путь к файлу |
| `WAF_MODSEC_LOG` | `info` | стартовый уровень журнала; живьём его переставляет панель |
| `WAF_HEARTBEAT_EVERY` | `4s` | период кадра присутствия |

`inspector.conf` из образа держит очередь (`queue_max 256`, `queue_full drop`) и адреса обоих
Redis по именам сервисов compose. Число 256 выбрано по буферу подписки клиента шины, а не по
очереди: на меньшем сообщения терялись молча на обычном дрожании планировщика.

## Docker Compose

```yaml
services:
  inspector-modsec:
    image: placitum/modsec
    scale: 5
    environment:
      NATS_URL: nats://nats:4222
      REDIS_URL: redis://redis:6379
      REDIS_INTERNAL_URL: redis://redis-internal:6379
      WAF_MODSEC_SUBJECT: waf.req.modsec
      WAF_MODSEC_NAME: modsec
      WAF_MODSEC_GEO_ADDR: geo:50051
    depends_on: [nats, redis, redis-internal]
```

Копий столько, сколько нужно: очередь шины раздаёт сообщения по кругу. CRS — самый дорогой
инспектор контура, и упирается он в процессор: на стенде копий пять.

## Проверка после запуска

Своего порта у инспектора нет; проверяют его тем же путём, что и работает, — сообщением по шине.
Проба лежит в образе и стоит в `HEALTHCHECK`:

```sh
docker exec <контейнер> modsec-probe --quiet --timeout 1s --uri /healthcheck
```

`start-period` у проверки — 20 секунд: набор CRS компилируется при старте, и до конца компиляции
подписки нет. Контейнер, который первые секунды «не отвечает», — это нормально.

В журнале при здоровом старте: загруженные профили, подключение к шине и обменнику, имя очереди,
число воркеров, затем `desired watch on` и применённое поколение.

## Грабли

- **Нет такого профиля — отказ, а не откат на `default`.** Разъезд тега маршрута и загруженных
  наборов иначе пропускал бы трафик непроверенным.
- **Версия схемы.** `WAF_MODSEC_VERSIONS` должен включать `2`: иначе каждый запрос уходит `allow`
  с `MODSEC_UNSUPPORTED_VERSION`, и CRS не смотрит вовсе.
- **Компиляция набора — это минута процессора на копию.** При одновременном старте пяти копий
  первая волна трафика до конца компиляции увидит политику дедлайна, а не вердикт.
