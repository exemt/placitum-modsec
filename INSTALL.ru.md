# Установка

[English](INSTALL.md) · Русский

Инспектор не слушает сеть: он подписчик очереди на шине. Адрес и сервис ему не нужны, и добавление
копии не трогает ни узел защиты, ни конфигурацию. Обычно его ставит `placitum-core`.

## Что нужно рядом

| Компонент | Обязателен | Зачем |
| --- | --- | --- |
| NATS | да | очередь `waf.req.modsec`, аудит, журнал, поколение профилей |
| Redis: обменник | да | тела запроса и ответа по локатору; недостижимый обменник роняет старт |
| Redis: внутренний | да | блобы поколения: профили, файлы данных, политика |
| Контроллер | да | шлёт профили поколением |
| `geo` | для записей сети и системы | анонсы и номер системы по адресу |

## Настройки

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `NATS_URL` | `nats://127.0.0.1:4222` | шина |
| `REDIS_URL`, `REDIS_INTERNAL_URL` | из `inspector.conf` | обменник и внутренний Redis |
| `WAF_MODSEC_SUBJECT` | `waf.req.modsec` | подписка; должна совпадать с `subject=` в объявлении инспектора |
| `WAF_MODSEC_NAME` | `modsec` | имя в реестре инспекторов и в кадре присутствия |
| `WAF_MODSEC_QUEUE` | имя | очередь шины |
| `WAF_MODSEC_PROFILES` | `./profiles`; в образе `/app/profiles` | профили до первого поколения |
| `WAF_MODSEC_DATA` | `<профили>.applied`; в образе `/var/lib/waf/modsec` | куда раскатка кладёт применённое поколение |
| `WAF_MODSEC_STATUS_MAP` | `./status_map.yaml`; в образе `/app/status_map.yaml` | статус движка в имя страницы отказа |
| `WAF_MODSEC_DENY_RULE_IDS`, `WAF_MODSEC_DENY_TAGS` | пусто | правила и метки, срабатывание которых — отказ, а не вклад в счёт |
| `WAF_MODSEC_RESUME_MAX` | `4 × queue_max` | сколько открытых транзакций ждут своей фазы ответа |
| `WAF_MODSEC_RESUME_TTL` | `30s` | сколько ждёт открытая транзакция |
| `WAF_MODSEC_SECRETS` | пусто | каталог секретов, если профили на них ссылаются |
| `WAF_MODSEC_GEO_ADDR` | пусто | кодер гео (`host:port`); пусто — записи сети и системы отвечают `error` |
| `WAF_MODSEC_GEO_TIMEOUT`, `WAF_MODSEC_GEO_NEG_MAX` | `500ms`, `0` | ожидание кодера в бюджете сообщения и потолок отрицательного кэша |
| `WAF_MODSEC_CONF` | `inspector.conf` в рабочем каталоге, затем `/app/inspector.conf` | очередь и адреса Redis |
| `WAF_MODSEC_WORKERS` | число ядер | воркеры движка |
| `WAF_MODSEC_QUEUE_DEPTH`, `WAF_MODSEC_QUEUE_FULL`, `WAF_MODSEC_QUEUE_EXPAND` | `256`, `drop`, `off` | очередь и поведение при переполнении; то же через `inspector.conf` |
| `WAF_MODSEC_RESERVE_MS`, `WAF_MODSEC_MIN_BUDGET_MS` | `2`, `3` | запас на ответ и минимальный бюджет, ниже которого движок не запускается |
| `WAF_MODSEC_VERSIONS` | `2` | версии схемы сообщения, которые процесс принимает |
| `WAF_MODSEC_LOG` | `info` | стартовый уровень журнала; живьём его переставляет панель |
| `WAF_HEARTBEAT_EVERY` | `4s` | период кадра присутствия |
| `WAF_LOG_SHIP` | `on` | уезжает ли журнал процесса на шину; `off` оставляет только stdout |

## Docker Compose

```yaml
services:
  inspector-modsec:
    image: placitum/modsec
    scale: 5
    environment:
      NATS_URL: nats://nats:4222
      REDIS_URL: redis://redis:6379
      REDIS_INTERNAL_URL: redis://redis-internal:6379
      WAF_MODSEC_GEO_ADDR: geo:50051
    depends_on: [nats, redis, redis-internal]
```

Копий столько, сколько нужно: очередь шины раздаёт сообщения между ними. CRS — самый дорогой
инспектор, и упирается он в процессор.

## Проверка

Своего порта у инспектора нет, поэтому проверяют его тем же путём, что и работает, — сообщением по
шине. Проба лежит в образе и стоит в `HEALTHCHECK`:

```sh
docker exec <контейнер> modsec-probe --quiet --timeout 1s --uri /healthcheck
docker exec <контейнер> modsec-probe --uri "/?id=1%27+or+1%3D1--"
```

Второй вызов должен вернуться со счётом. `start-period` у проверки — 20 секунд: CRS компилируется при
старте, и до конца компиляции подписки нет.

В журнале при здоровом старте: загруженные профили, подключение к шине и обменнику, имя очереди,
число воркеров, затем `desired watch on` и применённое поколение.

## Грабли

- **Незнакомый профиль — ошибка, а не откат на `default`.** Иначе разъезд тега маршрута и загруженных
  наборов пропускал бы трафик непроверенным.
- **Компиляция набора стоит процессора.** При одновременном старте нескольких копий первая волна
  трафика до конца компиляции увидит политику дедлайна, а не вердикт.
- **Усечённое тело не проверяется.** Маршрут с `waf_body_limit … trim` получает от modsec `error` с
  `MODSEC_BODY_TRUNCATED`, а не проверку.
