# profiles

Наборы правил SecLang. Один набор на всю транзакцию HTTP — фазы 1–5, обе стороны, — а не по набору на
фазу: транзакция живёт весь запрос, и фазы 3–4 доигрываются поверх состояния фаз 1–2
([«Главное ограничение»](../README.md#главное-ограничение-stateless-вызов-вместо-транзакции)).
Разделять наборы по фазам значило бы держать две копии CRS и терять между ними ровно то, ради чего
правила ответа и пишутся, — контекст запроса.

| Каталог | Что в нём |
| --- | --- |
| [`http/`](http/README.md) | Транзакция HTTP: `REQUEST-*` и `RESPONSE-*` в одном наборе |

Уровень каталога при этом остаётся, и остаётся не для красоты: раздача конфигурации
([`internal/desired`](../internal/desired/README.md)) подменяет его целиком переименованием, а
переименовывать ей нужно что-то одно. У кадров WebSocket будет свой набор и свой каталог — это не
транзакция HTTP, и правила CRS к ней неприменимы.

**Одна подпапка — один профиль.** Внутри набора правила лежат по подкаталогу на имя профиля:
`profiles/http/default/`, `profiles/http/strict/` и так далее — имя подкаталога и есть имя профиля,
которое `internal/rules` ищет по тегу `route.profile` из сообщения (профиль выбирается по этому
явному тегу, а не по инспектору и не по угадыванию маршрута — подробности в
[`internal/rules`](../internal/rules/README.md)). Подкаталог `default` обязателен и проверяется при
старте инспектора: это профиль маршрутов без явного `profile=` в `waf_inspector`. Профилем для
чужого, незагруженного имени он не служит — на такой тег инспектор отвечает `verdict: error`.

Формат файлов внутри подкаталога профиля — обычный SecLang (`.conf`), совместимый с тем, что принимают
libmodsecurity и Coraza: включение CRS как поставляемого набора плюс локальные
`SecRuleRemoveByTag`/`SecAction` сверху, без редактирования самого CRS.

Загрузка при старте и при обновлении обязана быть атомарной для каждого профиля независимо: набор
собирается и проверяется целиком до подмены указателя, см.
[`internal/rules`](../internal/rules/README.md).
