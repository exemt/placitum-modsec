# internal/rules

Выбор профиля правил по маршруту и его атомарная подмена при обновлении — то, что происходит
до вызова `internal/engine`, а не внутри него.

**Выбор по явному тегу `route.profile`, а не по угадыванию маршрута.** Поле `route.profile` сообщения
— имя, подставленное модулем nginx из `profile=` записи реестра для
server/location, откуда пришёл запрос; профиль на маршрут дешевле, чем инспектор на профиль, который
бы жёг биты из лимита в 64 имени инспектора на конфигурацию
(modsecurity-inspector.md#правила-и-их-жизненный-цикл (`docs/research/modsecurity-inspector.md`)).
Этот пакет больше не разбирает `route.server_name`/`route.location` и не хранит свою карту маршрутов
nginx — именно от этого дублирования конфигурации избавляет явный тег.

Значение `route.profile` полностью непрозрачно для nginx: тот не знает, какие профили загружены у
инспектора, и не может проверить тег при `nginx -t`. Профиль, для которого нет подкаталога
`profiles/http/<profile>/`, — расхождение двух репозиториев конфигурации, и `Select` отвечает на него
пустым движком: набора правил нет, обработчик отдаёт `verdict: error`.

Выбора между «откатиться на default» и «отказать» здесь больше нет. Первое отвечало по чужому набору
правил, выдавая эту проверку за проверку маршрута; второе блокировало трафик за ошибку
развёртывания. Оба были решением маршрута, и говорит его теперь `waf_exception <фаза> inspector`.

Независимо от выбранной политики каждое такое расхождение увеличивает отдельный счётчик метрик
(например `modsec_unknown_profile_total{profile=...}`) — тег из nginx и реально загруженные профили
живут в двух разных репозиториях конфигурации, и без счётчика разъезд между ними был бы виден только
по жалобе на трафик, прошедший не по тому набору правил. Профиль `default` обязателен и проверяется
при старте процесса: без него откат по политике `default` был бы отказом самого инспектора.

Сигнал обновления — watch KV в [`internal/desired`](../desired/README.md): новое поколение
пишется в staging, компилируется, и только успех зовёт `ReloadFrom`.

**Подмена — атомарная.** Новый набор собирается целиком в фоне, проверяется (ошибка компиляции
правил — это отказ обновления, а не частичное применение), и только после этого публикуется указатель
для чтения воркерами. Набор правил у обоих кандидатов движка потокобезопасен только на чтение, и
загрузка в живой набор — известный источник падений; порядок «собрать → проверить → подменить
указатель → дать старому дожить до завершения транзакций» соблюдается без исключений.

**Набор один на обе стороны транзакции.** Профиль покрывает фазы 1–5: продолжение (липкость)
доигрывает фазы 3–4 на той же транзакции, а откат переигрывает фазы 1–2 тем же набором. Двух наборов
на фазу больше нет — они означали бы две копии CRS и потерю контекста запроса между ними; что набор
держит выключенным и почему, см. [`profiles/`](../../profiles/README.md).

Отчитывается каждая сторона за свои фазы (`matchedPhases` в `internal/engine`), поэтому находки фаз
1–2 не приезжают в аудит второй раз вместе с вердиктом ответа.

Ошибка в профиле — неизвестный `SecAction`, обратная ссылка в regex, которую не примет RE2 у Coraza —
обнаруживается при старте процесса или при получении сигнала обновления, а не на первом запросе:
инспектор, который из-за опечатки в профиле начинает всё пропускать, хуже отказавшего.
