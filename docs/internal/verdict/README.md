# internal/verdict

Перевод вмешательства движка (`status`, `pause`, `url`, `log`, `disruptive`) в вердикт протокола.
Полная таблица соответствия — в
docs/research/modsecurity-inspector.md#отображение-вмешательства-на-вердикт (`docs/research/modsecurity-inspector.md`)
и продублирована в [основном README](../../README.md#вердикт-и-калибровка-счёта).

Два правила канала, за которые отвечает именно этот пакет, а не модуль:

- **`status` и `url` с провода не подставляются в ответ.** Только символьное имя записи каталога, по
  маленькой явной таблице `status_map` (403/406 → `blocked`, 400 → `malformed`, default → `blocked`,
  настраивается через `WAF_MODSEC_STATUS_MAP`). Само наличие вмешательства не значит, что у
  инспектора есть право решить, какую страницу показать клиенту — это делает конфигурация nginx.
- **`log` не покидает событие аудита.** Это полный текст сообщения правила с фрагментом
  совпавших данных, то есть кусок пользовательского ввода; помещать его в заголовок ответа —
  соблазн, который стоит пресечь на уровне типов, а не полагаться на дисциплину вызывающего кода.

Калибровка счёта — отдельная функция, не тождественное отображение аномального счёта CRS:

```
score = min(100, round(100 × crs_anomaly_score / crs_threshold / 2))
```

Знаменатель с двойкой — «двукратное превышение порога CRS = полная уверенность инспектора»; точная
форма калибруется на своём трафике в `mode=passive`
(docs/inspectors.md#выбор-между-score-и-deny (`docs/inspectors.md`)),
но преобразование как таковое обязано существовать до первого мандатного запроса — сырое число CRS и
`score` протокола измеряют разное и не сопоставимы напрямую. Сырые `crs_anomaly_score`,
`crs_threshold` и порог правила остаются в `engine` события `kind=inspector` для разбора инцидентов.
