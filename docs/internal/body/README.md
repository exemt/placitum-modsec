# internal/body

Получение тела по локатору из сообщения — единственное место инспектора, которое обращается к
внешнему хранилищу. Контракт общий для всех инспекторов
(docs/inspectors.md#получение-тела (`docs/inspectors.md`)), здесь —
специфика движка правил, для которого тело обычно не опция, а основной источник находок.

Четыре формы локатора обязаны быть обработаны все:

| Форма | Действие |
| --- | --- |
| `null` | Тело не участвует, движку передаются только фазы 1–2 |
| `{"inline": ...}` | Декодировать base64, передать в движок как есть |
| `{"store", "driver": "redis", "key", ...}` | Прочитать по ключу из Redis |
| `{"unavailable": ...}` | **Не решать за модуль, но и не проверять.** Ответ — `verdict: "error"` с кодом `MODSEC_BODY_UNAVAILABLE` и `engine.body = "unavailable:<причина>"` в аудите; исход выбирает `waf_exception … inspector` маршрута |

Дополнительно:

- **`truncated: true` — тоже не проверка.** Движку нужно тело целиком: префикс структурированного
  тела документом быть перестаёт, и молчаливая трактовка префикса как целого — источник ложных
  пропусков. Движок не запускается, ответ — `error` с кодом `MODSEC_BODY_TRUNCATED` и
  `engine.body = "truncated"`. Один помощник `bodyError` в `cmd/modsec` на все три фазы.
- **У префикса `sha256` не сверяется.** Сумма в локаторе — сумма оригинала: она связывает событие с
  архивом, а в хранилище при `waf_body_limit ... trim` лежит только начало тела, и совпасть
  эти суммы не могут по построению. Причина в ответе должна быть `truncated`, а не
  `digest_mismatch`: по первой ясно, что чинить маршрут, по второй — искать сбой обменника.
- **Шифрование** (`enc` в локаторе): ключ приходит из `internal/config`/секретов инспектора по
  `kid`, не с провода. Расшифровка AES-256-GCM, затем проверка `sha256` — она одновременно
  подтверждает целостность и даёт ключ кеширования вердикта по содержимому.
- **`body=preview` со стороны объявления инспектора — не наш случай.** Инспектор объявляется с
  `body=full`: префикс структурированного тела документом быть перестаёт, движок выставляет
  `REQBODY_ERROR`, и содержимое запроса не разбирается вовсе, см.
  [«Тело» в основном README](../../README.md#тело).

Ошибка чтения из Redis (таймаут, недоступность) — тоже `unavailable`, а не ответ без вердикта:
молчание неотличимо от перегрузки для модуля и стоит ему полного дедлайна.
