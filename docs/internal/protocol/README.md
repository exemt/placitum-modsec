# internal/protocol

Формат обоих сообщений типами, разбор входящего, сборка ответа — на Go и для инспектора,
которому дополнительно нужна секция `route` (в том числе `route.profile` — имя набора правил для
выбора в [`internal/rules`](../rules/README.md), непрозрачное для этого пакета: он его только
читает и передаёт дальше, без интерпретации) и полный `body`-локатор со всеми формами, включая `enc`
(шифрование).

Источник истины — `docs/verdict-protocol.md`; расхождение с
ним ловится тестами этого пакета, а не на живом трафике. Правило совместимости из протокола:
незнакомые поля игнорируются, поэтому типы описывают минимум, на который инспектор вправе
рассчитывать, а не полный список того, что может приехать по проводу.

Обязательные проверки при разборе, до передачи сообщения дальше по пайплайну:

- `v` — известная версия схемы; иначе `deny` с `reason.code = MODSEC_UNSUPPORTED_VERSION`, не
  allow и не молчание.
- `rid` — непустой, возвращается в любом ответе, включая ответы на ошибки разбора.
- `inspector` — своё имя; используется как есть при формировании ответа, а не берётся из
  конфигурации (см. предупреждение в [../../test/README.md](../../test/README.md#переменные-окружения)).
- `body` — валиден как одна из четырёх форм локатора
  (body-storage.md#локатор (`docs/body-storage.md`)) либо `null`.

Сборка ответа гарантирует эхо `v` и `rid` и то, что `score` при наличии — целое 0..100; значение вне
диапазона — тоже ошибка этого пакета, а не то, что можно отправить на шину и разобраться в модуле.
