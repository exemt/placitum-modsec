# cmd/modsec

Точка входа процесса. По конвенции остальных пакетов Go в этом дереве (`internal/...`), `main.go`
здесь тонкий и не содержит логики решений — она в `internal/`.

Обязанности, в порядке инициализации:

1. Разбор конфигурации из окружения — `internal/config`.
2. Загрузка профилей правил и создание движка — `internal/rules`, `internal/engine`.
3. Подключение к шине, `QueueSubscribe` на subject из конфигурации, в queue group по умолчанию
   равной имени инспектора (`modsec`), по аналогии с [../../test/README.md#переменные-окружения](../../test/README.md#переменные-окружения).
4. Запуск пула воркеров `internal/queue` поверх принятых сообщений.
5. Watch KV `WAF_DESIRED/policy/modsec` — `internal/desired`: новое поколение компилируется и
   подменяет набор, не останавливая подписку.
6. Дренаж по сигналу (`SIGTERM`): подписка снимается, воркеры дожидаются текущих транзакций, процесс
   выходит. Без дренажа `reload` инспектора выглядит как всплеск политики `waf_deadline` на его subject.

Ответ отправляется на каждом пути без исключения, включая панику внутри обработки одного сообщения —
она обязана быть перехвачена здесь и превращена в `allow` с машинным кодом причины, а не в падение
процесса. Молчание неотличимо от перегрузки, см.
inspectors.md#контракт (`docs/inspectors.md`).

Появляется на этапе 4 `docs/roadmap.md` как прототип без тела, дополняется
получением тела на этапе 6.
